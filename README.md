# AI Zero

AI 없이 만들고 싶었던 작은 모듈을 직접 구현하고, 운영체제와 프로그램 실행 등 오래가는 기초 원리를 탐구합니다. 스스로 설계하고 동작을 이해하며, 문제가 생겼을 때 근거를 찾아 판단하는 개발 기본기를 쌓습니다.

Zero-To-Frontier는 변화의 방향을 탐색하는 Frontier와 오래가는 원리를 연구하는 Zero를 함께 운영합니다. 두 트랙은 각자의 흐름으로 진행하며, 주제를 매번 연결할 필요는 없습니다.

## 방향성

Zero는 최신 AI 기술을 공부하는 활동이 아니라, 기술이 바뀌어도 활용할 수 있는 개발의 기본기를 쌓는 활동입니다. 여기서 오래가는 지식은 메모리·프로세스·파일·동시성·네트워크 등의 원리입니다. Docker 같은 구체적인 기술은 원리가 실제로 어떻게 적용되는지 살펴보는 대상으로 삼습니다. 제품의 구현 세부사항이 모두 불변이라고 보지는 않습니다.

### 모듈 구현 회차

- 각자 만들고 싶었던 작은 모듈을 정하고 핵심 로직을 AI 없이 직접 설계·구현합니다. 모두 같은 모듈을 만들 필요는 없습니다.
- 목표와 기능 범위를 작게 잡아 한 번의 준비 기간 안에 핵심 동작을 확인합니다. 다음 구현 회차에는 기존 모듈을 개선하거나 새 모듈을 선택할 수 있습니다.
- 직접 이해하려는 핵심 로직에 집중하며, 주변 기능과 개발 도구까지 모두 처음부터 만들 필요는 없습니다.
- 구현 목적, 설계 선택과 이유, 동작을 확인한 방법, 막힌 지점과 해결 과정을 공유합니다.

### 기본 원리 탐구 회차

- 각자 관심 있는 기초 영역과 핵심 질문을 정하거나 공통 주제를 선택하고, 자료를 읽고 동작을 예측·관찰합니다. 실험 방법과 추가 탐구 깊이는 자율로 둡니다.
- 개념을 자신의 말로 설명하고, 왜 그런 동작이 생기는지와 어떤 조건에서 문제가 되는지 탐구합니다.
- 메모리 사용과 수명, 프로그램 실행 과정, 동시성, 컨테이너의 격리와 자원 관리 등이 탐구 대상입니다.
- 필요하면 작은 재현 코드·로그·디버거를 활용해 설명이 맞는지 확인합니다. 매번 완성된 모듈을 만들 필요는 없습니다.

### 두 활동의 관계

구현과 원리 탐구를 번갈아 진행하며, 한 회차에 두 가지 완성된 결과물을 요구하지 않습니다. 구현 중 필요한 이론을 찾아보거나 원리를 이해하기 위해 실험 코드를 쓰는 것은 자연스럽게 포함합니다.

구현에서 나온 질문을 다음 원리 주제로 삼을 수 있지만 연결은 필수가 아닙니다. 개인 구현에서 접하지 못한 핵심 기초도 별도로 공부합니다. Frontier 주제와의 연결 역시 필수가 아닙니다.

## 기록과 모임

- 각 회차는 저장소 루트의 `YYYYMMDD/` 폴더로 관리합니다. 날짜는 결과를 공유하는 모임 날짜입니다.
- 개인 기록과 코드는 자기 이름 폴더에 남기고, 회차 안내와 회의록은 돌아가며 맡는 기록 담당자가 반영합니다.
- 발표 자료는 필수가 아닙니다. 회차 유형에 맞는 짧은 기록과 증거를 준비합니다.
- 모임에서는 구현 회차의 설계·문제 해결 과정, 원리 회차의 설명·예측·관찰 차이를 나눕니다.
- 확인한 사실, 의견이 갈린 부분, 남은 질문, 다음 회차에 합의한 내용을 공동 기록으로 남깁니다.
- 회차 폴더를 진행과 기록의 기준으로 사용하며, Issues와 Projects는 필요할 때 도입합니다.

## 폴더 구조

아래 날짜와 이름은 구조를 설명하는 예시이며, 실제 회차 일정과 참여자를 확정한 것은 아닙니다.

```text
YYYYMMDD/
├── README.md        # 회차 유형·주제·일정·범위
├── 윤호/
│   └── README.md    # 개인 기록과 실험 코드
├── 동민/
│   └── README.md
└── meeting.md       # 공동 회의록과 결론
```

## 학습 기준

- **설명:** 코드와 시스템이 왜 그렇게 동작하는지 자신의 말로 설명할 수 있는가?
- **예측:** 입력이나 실행 조건이 바뀌면 어떤 일이 생길지 예상할 수 있는가?
- **검증:** 자신의 설명과 예상이 맞는지 실험·테스트·디버깅으로 확인할 수 있는가?

완성 여부나 속도보다 가설과 검증 과정을 봅니다. 미완성이어도 시도한 것·관찰한 것·아직 모르는 부분을 공유합니다. 공부에 쓴 시간이 길다는 이유만으로 성과를 판단하지 않습니다.

## AI와 자료 사용 원칙

- **모듈 구현:** 설계·구현·디버깅과 해결 방법 탐색을 직접 수행합니다. AI 코드 생성·자동완성·해결책 제시는 제한합니다. AI를 사용했다면 지점과 이유를 기록합니다.
- **기본 원리 탐구:** AI를 개념 설명·추가 질문·예시·실험 코드·이해 점검에 활용할 수 있습니다. 핵심 설명은 공식 문서·책 또는 실험으로 확인하고 자신의 말로 정리합니다. AI 도움을 받은 부분은 간단히 남깁니다.
- 두 활동 모두 공식 문서·책·기술 자료·검색·오픈소스 코드·디버거·프로파일러·일반 IDE 기능을 활용할 수 있습니다. 참고한 자료와 코드는 기록합니다.
- 동료와 질문과 힌트를 주고받을 수 있습니다. 기록의 목적은 감시가 아니라 자신이 이해하고 수행한 부분을 분명히 하는 것입니다.
